# Frontend localization

The frontend supports `en` and `vi`. `lib/constants.ts` is the canonical locale
contract: it owns the supported values, cookie name (`nexus.locale`), and the
`en` default. Invalid or missing preferences normalize to `en`.

Messages use `next-intl` with domain-scoped catalogues under `messages/{locale}`:
`common`, `auth`, `customer`, `provider`, and `administration`. Keys describe
meaning (`administration.authorization.roles.title`), not component position.
User-created role names, permission codes, UUIDs, and request IDs are never
translated.

`i18n/request.ts` is the server request configuration. It reads the same
normalized `nexus.locale` value as the root layout, supplies the five domain
catalogues, and keeps server-rendered and client-rendered translations on the
same locale. The API client uses that same normalization contract for `x-lang`.

The `nexus.locale` cookie is the canonical locale preference used by SSR and
API request language selection. The root layout reads the cookie so `<html
lang>` and the first server render agree. localStorage is only a client-side
mirror for compatibility and must never independently override the rendered
locale. The shared API transport sends the normalized cookie locale as the
backend's actual locale header, `x-lang`, on every client request. This is not
`Accept-Language` in PR #31.

Backend business errors remain authoritative. `ApiError.errorCode` drives
known frontend UX; the backend's localized `message` is the fallback for
unknown codes, and `request_id`/details remain available for diagnostics.

To add copy, add the same semantic key to both locale catalogues, then use
`useTranslations('domain')`. Keep API values and business comparisons in
their raw enum/code form and localize only presentation.

Run `npm run i18n:check` when adding or moving messages. CI validates that the
five domain catalogues remain structurally identical between English and
Vietnamese. Navigation copy belongs to the owning product domain; shared
shell labels and accessibility copy belong to `common`.
